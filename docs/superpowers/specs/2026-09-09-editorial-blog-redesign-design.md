# Ember 余烬博客大幅改版设计

日期：2026-09-09

## 1. 背景与目标

Ember 目前是一个 Astro 静态博客，已经具备文章、项目、搜索、标签、评论、RSS、深浅主题和中英文路由。现有界面把终端语言扩展到了导航、首页、正文和项目卡片的几乎所有区域，形成了明确的极客气质，但也带来几个直接问题：长文使用等宽字体导致阅读疲劳，桌面固定侧栏压缩内容，首页缺少清晰的阅读入口，项目卡片在 GitHub 描述为空时几乎不能传达项目价值。

本次改版采用“技术编辑部 + 视觉杂志”的融合方向。结构以阅读效率为中心，视觉通过真实项目素材、文章封面和一张“余烬”品牌位图建立辨识度。首页对文章与项目给予同等权重。

目标：

- 让访客在首屏内理解 Ember、内容主题和两个主要入口。
- 让中文技术长文在桌面和移动端都舒适、清晰且容易继续探索。
- 让项目页面说明项目解决的问题、作者职责和可验证成果。
- 让站内搜索、主题切换、移动导航和评论主题同步真正可用。
- 让新增文章和项目保持 Markdown 驱动，视觉字段可选，日常维护成本低。
- 纠正当前双语、SEO、订阅承诺和可访问性问题。

## 2. 非目标

本次不引入 CMS、账户、登录、后台管理、访问分析或邮件发送服务。不继续收集无法用于实际通知的订阅邮箱。不为缺少依据的项目编写虚构成果。不把站点改造成复杂的单页应用。

## 3. 设计原则

1. 内容先于装饰。终端符号只用于品牌、代码和少量元数据。
2. 两条主线并重。首页同时提供文章与项目入口，不让任何一条成为附属区。
3. 图片服务于识别和理解。首图表现“余烬”品牌，项目优先展示真实界面或硬件照片。
4. 默认状态必须可信。不可用的功能应被修复、降级或移除，不能用承诺性文案遮掩。
5. 渐进增强。没有 JavaScript 时，文章、项目、导航、主题默认样式和 RSS 仍可访问。
6. 中文优先。英文页面只展示真正存在的英文内容，不把中文回退内容声明成英文译文。

## 4. 信息架构

主导航保留五个入口：品牌首页、文章、项目、搜索、关于。RSS、GitHub、邮件和语言切换放在导航操作区或页脚，不与主要内容入口争夺视觉权重。

桌面端移除固定左侧栏，改用紧凑的顶部粘性导航。移动端使用原生模态对话框形式的抽屉导航，获得可靠的焦点约束、Escape 关闭和背景隔离行为。

页面结构：

- 首页：品牌首屏、文章与项目双重点区、最新文章、更多项目、RSS 行动区。
- 文章：精选入口、主题标签、按年份排列的文章列表。
- 文章详情：文章头部、正文、目录和阅读工具、相关文章、上一篇/下一篇、评论。
- 项目：精选案例、全部公开仓库、GitHub 外链。
- 搜索：查询输入、文章/项目分类、结果列表、明确的加载和失败状态。
- 关于：作者介绍、关注方向、联系方式和本站说明。
- 标签：仅展示当前语言的匹配文章。
- 404：返回首页、进入文章、进入项目和搜索入口。

## 5. 视觉系统

### 5.1 品牌与首屏

首页首屏使用一张原创位图：近距离的真实质感余烬或金属丝微光场景，构图在主体一侧保留清晰文字区域。图片作为全宽背景，品牌名“Ember 余烬”、作者定位、简短说明和“阅读文章 / 查看项目”两个入口直接叠在画面上，不放入卡片。使用纯色半透明遮罩保证文字对比度，不用渐变或装饰光球。

首屏高度受视口和固定上限共同约束。在常见手机和桌面视口中，首屏底部必须露出下一部分的标题或内容边缘。

品牌首图保存到 `src/assets/` 并交给 Astro 图片管线生成合适格式与尺寸。它是页面的优先视觉资源，其他图片延迟加载。

### 5.2 色彩

色彩由中性背景、余烬红和冷色功能色组成，避免单一色相：

- 深色背景使用近黑的中性炭色，不使用大面积深蓝。
- 浅色背景使用冷白和浅灰，不使用大面积奶油色或米黄色。
- 余烬红用于品牌、主要按钮和关键选中态。
- 冷青用于链接、信息状态和少量项目元数据。
- 苔绿色仅用于成功状态和技术标签。

颜色以语义变量暴露，例如 `--surface`、`--text`、`--accent`、`--link` 和 `--success`。所有正文、交互和焦点状态满足可读对比度。

### 5.3 字体与节奏

中文正文使用系统无衬线字体栈，英文与数字选择兼容的系统字体。文章标题可以使用更有编辑感的衬线回退，但不加载阻塞渲染的远程字体。等宽字体只用于品牌标记、代码、键盘输入和紧凑元数据。

正文行宽控制在 `68–72ch`，正文行高约 `1.8`，段落间距稳定。字体大小通过固定断点调整，不随视口连续缩放。卡片圆角不超过 8px。

### 5.4 背景与动效

普通页面背景使用纯色和非常轻的位图颗粒，不使用 SVG 点阵、渐变光晕或漂浮装饰物。内容区通过留白、细线和明暗层级分区，不把整个页面堆成卡片。

进入动效只保留短距离淡入，并遵守 `prefers-reduced-motion`。移除首页逐字打字动画，避免内容闪烁、等待和中英文脚本差异。

## 6. 页面设计

### 6.1 首页

首页不使用通用窄容器包住全部内容。品牌首屏全宽，后续区块使用统一内容宽度。

首屏之后是“本期重点”双轨区：左侧是一篇精选文章，右侧是一个代表项目。两者都使用稳定比例的视觉素材、简短摘要和清晰入口，在窄屏时顺序堆叠。随后展示最新文章列表与更多项目。项目和文章在首屏之后获得相近的视觉权重。

文章封面是可选字段。缺少封面时使用一套由标题、主题色和纹理构成的统一位图回退，不要求作者每次发布都制作图片。项目视觉优先使用真实截图、硬件照片或仓库的可验证预览；没有素材时使用中性的项目类型回退图，不伪造产品界面。

### 6.2 文章列表

列表页标题直接使用“文章 / Posts”，终端命令作为小型辅助标签，不进入主标题。顶部展示精选文章和常用主题，正文按年份分组。文章项包含标题、摘要、日期、预计阅读时长和标签，标题层级连续。

标签是标准链接，可在没有 JavaScript 时工作。首期不加入复杂的客户端多条件过滤，避免在仅三篇文章时增加无效复杂度。

### 6.3 文章详情

文章主列保持 `68–72ch`。大屏在右侧提供独立目录轨道，目录出现时不得压缩正文；中等和移动视口使用可展开目录。页面顶部提供细阅读进度条。

代码块提供图标形式的复制按钮和可访问提示。仅在 Clipboard API 可用时显示按钮，成功状态通过 `aria-live` 宣告。标题提供可聚焦的锚点链接。文末提供同标签相关文章、上一篇/下一篇和评论。

移除公开浏览量。当前实现每次加载即加一，刷新、爬虫和 KV 并发都会造成虚高，无法提供可信信息。

### 6.4 项目页

页面先展示三至五个精选案例。每个案例包含：项目要解决的问题、作者角色、技术栈、可验证亮点、年份或状态、源码和演示链接，以及真实截图或硬件照片。

案例信息来自本地 Markdown，便于作者长期维护。实现阶段可以读取公开仓库 README 整理事实，但不得推断无法验证的指标或结果。GitHub 仓库列表作为次级区块，缺少描述的仓库使用简洁列表呈现，不再生成大块空卡片。

### 6.5 搜索

中英文页面共用一个搜索组件。修复当前 `msgs.found` 和 `msgs.noResult` 未传入导致查询报错的问题。初始化完成后，如果用户已输入内容，应立即执行查询。

Pagefind 元数据包含 `lang`、`type`、标题和标签。中文搜索只返回中文内容，英文搜索只返回英文内容。文章与项目分类使用分段控件。搜索状态使用 `role="status"`，结果使用列表与标题语义。移动端不使用 `autofocus`，避免打开页面时强制弹出键盘。

结果渲染使用 DOM API，并只保留 Pagefind 摘要中必要的高亮标记，避免直接拼接不受约束的 HTML。

### 6.6 关于、页脚与 404

关于页从终端窗口改为开放排版，突出作者关注领域、代表工作和联系方式。站点实现细节保留为次级说明。

页脚移除邮箱订阅表单，改为明确的 RSS 行动区，同时提供 GitHub 和邮件联系。RSS 文案说明它是获取新文章的实际方式。

404 页面延续品牌视觉但保持轻量，提供四个恢复入口：首页、文章、项目和搜索。

## 7. 中英文与 SEO

中文是默认语言，删除基于浏览器语言的强制跳转。全局页面保留 `/en/` 路由，但英文文章列表只读取 `lang: en` 内容；没有英文文章时显示真实空状态和中文站入口。

文章增加可选 `translationKey`。只有同一 key 下确实存在另一语言文章时，才输出对应 `hreflang` 和文章级语言切换链接。英文文章详情路由不再生成中文文章的回退副本。

中文和英文标签页按内容语言过滤。`/rss.xml` 只输出中文文章并声明 `zh-CN`。在存在足够英文内容之前不创建伪英文订阅源。

所有页面输出 canonical。文章输出 `og:type=article`、发布日期、更新时间和封面；普通页面保持 `website`。缺少封面时使用站点级品牌分享图。

## 8. 内容模型与维护体验

文章 schema 在保留现有字段的基础上增加：

```ts
cover?: ImageMetadata
coverAlt?: string
featured: boolean
series?: string
translationKey?: string
```

有 `cover` 时必须有非空 `coverAlt`。`featured` 默认 `false`。所有新增字段可选或有默认值，现有 Markdown 无需一次性迁移即可继续构建。

项目 schema 增加：

```ts
lang: 'zh' | 'en'
featured: boolean
status?: string
role?: string
highlights: string[]
image?: ImageMetadata
imageAlt?: string
```

精选项目继续放在 `src/content/projects/`。README 增加可直接复制的文章和项目 frontmatter 示例，说明封面为可选项、图片位置和中英文规则。

## 9. 组件与代码结构

保留 Astro 静态输出，不引入前端框架。页面通过共享组件接收 `lang`，消除现有中英文页面复制导致的行为漂移。

计划形成以下职责边界：

- `BaseLayout.astro`：文档骨架、SEO、主题初始化、跳过导航和页面宽度模式。
- `Header.astro`：品牌、主导航、语言、搜索入口、主题和移动菜单。
- `Hero.astro`：品牌首屏及其优化图片。
- `HomePage.astro`：按语言组合首页内容，不重复路由实现。
- `PostIndexPage.astro`、`ProjectsPage.astro`、`SearchPage.astro`、`TagPage.astro`：共享页面主体。
- `PostCard.astro`、`ProjectCard.astro`：可复用内容项，接受明确的标题层级和显示模式。
- `PostPage.astro`：文章正文、目录、相关文章和阅读工具。
- `Footer.astro`：RSS、社交入口与版权。

`Sidebar.astro` 和终端式 `TypeHero.astro` 在新结构中退出。图标使用可按图标单独打包的 Lucide Astro 组件，按钮保持图标化并提供本地化名称和提示。

全局样式只承担设计变量、重置、字体、通用布局和 Markdown 正文。组件视觉尽量放在对应 Astro 组件的局部样式中，遵循 Astro 的样式作用域和导入顺序。

## 10. 交互与可访问性

- 页面最前提供“跳到正文”链接，`main` 有稳定目标 id。
- 当前导航使用 `aria-current="page"`，所有交互具备一致的 `:focus-visible`。
- 主题初始值在没有用户存储选择时遵从系统偏好；按钮名称随当前状态更新。
- 移动菜单使用原生 `dialog`，关闭后焦点回到触发按钮。
- 语言、关闭、搜索、邮件等可访问名称全部本地化。
- 装饰符号不参与无障碍名称，标题层级连续。
- 触控目标至少约 44px，固定工具不会遮挡正文或系统安全区域。
- 图片提供替代文本和明确宽高；纯装饰纹理使用空替代文本。
- 表格放入可横向滚动的容器或应用等价样式，不能撑破移动页面。
- 所有动画遵守减少动画偏好。
- Giscus 监听实际主题按钮，并通过 `postMessage` 同步主题。

## 11. 数据流与降级

构建时从 Astro content collections 读取文章和精选项目，从 GitHub API 读取公开仓库。GitHub 请求失败时继续使用 `src/data/github-repos.json`，页面应显示缓存数据而不是构建失败。

Pagefind 在生产构建后生成索引。索引加载失败时，搜索页显示可操作的失败说明和文章/项目入口。开发模式明确说明搜索索引仅在完整构建中可用。

封面缺失时选择品牌回退图。单张内容图片失败不能影响标题、摘要和链接。脚本异常不能隐藏服务端已经输出的主要内容。

## 12. 性能约束

- 保持静态 HTML 和最少客户端 JavaScript，不做全站 hydration。
- 首图使用 Astro 图片优化、`srcset` 和明确尺寸；首图以外图片延迟加载。
- 不加载远程字体，不引入完整 UI 框架。
- Lucide 图标按组件导入，避免整包输出。
- 背景颗粒是尺寸受控的压缩位图，不使用大尺寸透明 PNG。
- 页面载入后不运行持续装饰动画；北京时间时钟从主要导航移除。

## 13. 验收标准

功能：

- `npm run build` 成功，并生成可查询的 Pagefind 索引。
- 中文搜索可以返回文章和项目结果，无控制台异常；空查询、无结果和索引失败均有正确状态。
- 主题切换、移动菜单、目录、代码复制、标题锚点和评论主题同步可用。
- RSS 只包含中文文章，所有条目链接有效。
- 中英文主页、列表、标签和文章路由只展示对应语言内容。
- 404 页面可访问，并能回到主要内容。

视觉与响应式：

- 在 390x844、768x1024、1024x768 和 1440x900 视口检查首页、文章、项目和搜索。
- 没有横向页面溢出、文字遮挡、按钮截断或固定元素覆盖内容。
- 首页首屏清楚显示“Ember 余烬”并露出下一部分。
- 正文保持约 `68–72ch`；目录出现或消失时正文宽度不会突变。
- 深浅主题均具有清晰层级和足够对比度。

可访问性与稳定性：

- 仅用键盘可以完成主导航、搜索、菜单、主题切换、目录和代码复制。
- 移动菜单关闭时不进入焦点顺序，Escape 可关闭，焦点正确恢复。
- 页面具有跳过导航、连续标题层级、当前页面状态和动态状态播报。
- `prefers-reduced-motion` 下没有强制进入动画或打字效果。
- 浏览器控制台没有由站点代码产生的错误。

## 14. 实施边界

实施将分为设计系统与布局、共享页面与内容模型、阅读工具与搜索、项目内容与视觉资产、双语与 SEO、验收修正六个部分。每部分完成后运行与其风险相称的检查，最终进行完整构建和多视口浏览器验收。
